## Commits e Pull Requests

### Padrões de Commits

Este projeto utiliza o padrão **Conventional Commits** para manter um histórico claro e organizado.

#### Boas práticas
- Faça **commits pequenos e descritivos**.
- Quando possivel cada commit deve representar **uma única mudança**.
- Use mensagens na **forma imperativa** (ex.: “adiciona”, “corrige”, “remove”).
- Evite commits genéricos como “update” ou “ajustes”.

#### Exemplos de messagem de commits
```yaml
feat: adiciona validação de email no formulário
fix: corrige bug no login quando senha está vazia
docs: atualiza instruções de instalação
chore: atualiza dependências do projeto
refactor: simplifica lógica de autenticação
test: adiciona testes para componente de login
```

## Prefixos utilizados

Abaixo estão os prefixos aceitos de acordo com o padrão **Conventional Commits**:

- **feat** → nova funcionalidade  
- **fix** → correção de bug  
- **docs** → mudanças na documentação  
- **style** → formatação/estilo (sem alteração funcional)  
- **refactor** → refatoração sem alterar comportamento  
- **test** → criação ou ajuste de testes  
- **chore** → tarefas auxiliares (build, dependências, configurações)
